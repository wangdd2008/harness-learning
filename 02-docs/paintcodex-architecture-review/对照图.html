PaintCodex 现状架构 → 企业级 Agent 架构对照
对照《AI Agent 实战手册》第 2 章五责任域与第 3 章构建方式 · 绿=已落实 橙=部分 红=缺口
① 现状 · 单机教学版（高代码自建 Harness）
Agent 构建与编排层
CodexRuntime（唯一接缝）· 拉为主 Context · 8 工具 · 确认通道（fail-closed）· 失败对模型可见 · actor 归因 + revision 并发
生产运行层
Fastify + SQLite(WAL) · 一画布一 thread（id 持久化）· 崩溃懒重启 · 无队列 / 无 Checkpoint / 无 Task 表
治理与控制层
sandbox read-only · SVG 白名单 · 版本闸门（codex≥0.164）· ADR 文档 · 无 Policy 集中定义 / 无身份租户
可观测（雏形）
agent_logs + 四级 trace + source→target 拓扑 + monitor 页 · 无成本 / 无 Outcome / 无评估基线
② 差距（改造点）
P0 无 Task/Session/Checkpoint → turn 不可恢复
P0 会话状态在 Codex 内部 → 无审计/迁移
P0 无 Agent Release → 不可复现/回滚
P0 无评估闭环 → 无法证明改进
P0 单用户无身份/租户/配额
P1 权限策略硬编码 · 无 AI Gateway · 无 Memory/Knowledge · 依赖浏览器渲染
P2 协议手写子集无 CI · 重复实现 · 日志无保留策略
③ 企业级目标（阶段 A→B→C）
A 稳定内核
Task/Session/Event/Checkpoint 表 · Agent Release（releaseId 入 trace）· CI+协议漂移门禁 · 最小评估基线 · 成本/Outcome 记录
B 企业化
身份/租户/IAM · 集中 Policy（allow/deny/ask）· AI Gateway（路由/限流/成本）· 服务端制品存储 · 任务队列+幂等恢复 · Memory/Knowledge
C 平台化
执行面/数据资源面/控制面三平面分离 · 多 Agent+Handoff · 容器沙箱 · 托管+私有执行面部署
构建方式判定： 第 3 章四类入口中属于 「高代码 Agent Framework 自主构建 Harness」的极简个人版——Loop/Context/状态语义/工具策略/验证全自建； 局部复用 Codex 产品能力（thread 持久化 + read-only 沙箱）；评估与业务验收两项责任空白（表 3-2 企业仍需承担列）。 核心建议：先让每次任务「可恢复、可复现、可判定」（A），再治理与多用户（B），最后平台化（C）；不引入通用 Framework，保留人机同权差异化。
