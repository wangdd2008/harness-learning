### 常见问题（FAQ）

**审查面板出现 Codex 没有改动过的文件**

如果你的项目位于 Git 仓库内，审查面板会自动依据项目的 Git 状态展示变更，包括那些并非 Codex 做出的改动。在审查面板中，你可以在已 staged 与未 staged 的变更之间切换，也可以把当前分支与 main 做对比。如果你只想看最近一次 Codex 回合的改动，把 diff 面板切到 **Last turn** 视图即可。审查面板的详细用法见站点文档路径 /docs/code-review。

**从侧边栏移除项目**

把鼠标悬停在项目名上，选择三个点菜单，再选 **Remove** 即可从侧边栏移除项目。如需恢复，点击 **Chats** 旁边的 **Add new project** 按钮重新添加，或使用 <kbd>Cmd</kbd>+<kbd>O</kbd>。

**查找已归档的对话**

已归档的对话可以在 Settings（`codex://settings`）中找到。当你把某个对话取消归档时，它会重新出现在侧边栏的原位置。

**某个 Work 对话在另一台设备上不显示**

- 确认每台设备都以同一个 ChatGPT 账号、同一个 workspace 登录。
- 请你的 workspace owner 检查 Work Cloud 与 **Allow local computer access** 是否启用。如果任何云策略启用了 `enforce_residency`，则 **Allow local computer access** 对 Work 与 dots 都会被禁用。这一保护措施本身并不配置 workspace residency，也不会单独禁用 Work Cloud 或 dots。
- 检查任务的创建时间。同步只对启用之后新建的任务生效；已存在的任务（包括属于某个 project 的任务）不会被迁移，会保持其原本的"仅本地"或"云但无本地文件"行为。

对企业而言，发布时应用内的 Local/Cloud 开关及其默认值保持不变；某个开关或默认模式本身并不能断定一个对话能否同步。查找 Work 对话时，请把 Codex 历史区分开。搭建与常见问题分别见站点文档路径 /docs/enterprise/cloud-local-access 与 /docs/enterprise/work-admin-faq。

**已同步的任务无法使用本机的文件或工具**

保持本机在线并处于连接状态。当新回合启动时如果本机不可用，符合条件的已同步任务可以在云容器中继续运行，但无法访问本机的文件与工具；正在运行中的回合不会自动从本机迁移到云端。

**关闭 Work Cloud 的 Local computer access 后回合中断**

关闭 Work Cloud 的 Local computer access 会中断正在运行的回合。如果你仍有 Work 访问权限，发送一条新消息即可启动另一个回合；在已存在的云对话中，该回合会自动使用 Work Cloud，且无法访问本地文件。

**自动化策略更新缺失**

使用 policy API 管理 Global 设置；管理 Local 或 Codex Cloud 设置则使用 Agent Security UI。迁移后，既有的 Global API 工作流仍然可用。请测试你的脚本与 Terraform 集成，确认策略分配与顺序没有变化。

**侧边栏只显示部分对话**

侧边栏允许你依据 project 状态筛选对话。如果发现对话缺失，点击 **Chats** 旁边的筛选图标，再选 **Chronological**。如果仍然看不到该对话，打开 Settings（`codex://settings`）检查 **Archived chats**。

**代码在 worktree 上跑不起来**

worktree 创建在另一个目录中，默认只继承已签入 Git 的文件。依据你管理依赖与工具链的方式，你可能需要在 worktree 上用[本地环境](07-环境与沙箱.md)跑一遍安装脚本，或者用 `.worktreeinclude` 把被忽略的安装文件复制进受管 worktree（详见[环境与沙箱](07-环境与沙箱.md)中关于 git-worktrees 的章节）。你也可以在常规本地项目中检出这些改动。更多说明见站点文档路径 /docs/environments/git-worktrees。

**应用没有识别到队友共享的本地环境**

本地环境配置必须放在项目根目录的 `.codex` 文件夹内。如果你在一个包含多个 project 的 monorepo 中工作，请确保你打开的项目路径就是包含 `.codex` 文件夹的那一层。

**Codex 请求访问 Apple Music**

依据任务不同，Codex 可能需要导航文件系统。macOS 上的某些目录——包括 Music、Downloads、Desktop——需要用户额外授权。如果 Codex 需要读取你的 home 目录，macOS 会提示你批准对这些文件夹的访问。

**定时任务创建了大量 worktree**

频繁的定时任务会随时间创建大量 worktree。归档你不再需要的定时运行记录；除非你打算保留其 worktree，否则不要 pin 运行记录。

**选错目标后如何恢复 prompt**

如果你不小心以错误的目标（**Local**、**Worktree** 或 **Cloud**）开启了对话，可以取消当前运行，然后在输入框中按上箭头键恢复之前的 prompt。

**Approve for me 缺失或被禁用**

要使用自动审查，在输入框下方的权限控制中选择 **Approve for me**。如果该模式缺失或被禁用：

1. 更新桌面应用，并在你想使用自动审查的那个对话中检查权限菜单。本地环境与云环境下可选项可能不同。
2. 对本机 Codex 执行，检查你的生效配置中是否显式设置了 `features.guardian_approval = false`，并核对已配置的权限 profile、审批策略与审批 reviewer。配置优先级见[配置基础与示例](04-配置-基础与示例.md)。本地配置无法控制受管云运行时。
3. 如果某个模式在受管 workspace 中被禁用或缺失，请让管理员检查允许的权限 profile、沙箱模式、审批策略与审批 reviewer。组织或设备策略可以限制这些可选项，本地设置无法覆盖。

如果该模式仍然意外不可用，请在反馈中附上你的应用版本、操作系统、执行环境，以及该选项是"缺失"还是"被禁用"。

**功能在 Codex CLI 中可用，但在 ChatGPT 桌面应用中不可用**

ChatGPT 桌面应用与 Codex CLI 可能内置了不同的 Codex 版本，因此功能可能先到达其中一个入口。

查看本机 Codex CLI 版本：

```bash
codex --version
```

查看 ChatGPT 桌面应用内置的 Codex 版本（使用保留的 `Codex.app` 兼容包路径）：

```bash
/Applications/Codex.app/Contents/Resources/codex --version
```

### 反馈与日志

在消息输入框中输入 <kbd>/</kbd> 即可向团队提交反馈。如果你在一个已存在的对话中触发反馈，可以选择把当前会话一并共享。提交反馈后，你会收到一个 session ID，可以把它提供给团队。

上报问题的步骤：

1. 先在 Codex GitHub 仓库（github.com/openai/codex/issues）中查找是否已有同类 issue。
2. 通过 github.com/openai/codex/issues/new 入口新开一个 bug 报告 issue。

更多日志位于以下位置：

- 应用日志（macOS）：`~/Library/Logs/com.openai.codex/YYYY/MM/DD`
- 会话 transcript：`$CODEX_HOME/sessions`（默认 `~/.codex/sessions`）
- 已归档会话：`$CODEX_HOME/archived_sessions`（默认 `~/.codex/archived_sessions`）

共享日志前请先自行检查，确认其中不含敏感信息。

### 卡住状态与恢复套路

如果某个对话看起来卡住了：

1. 检查 Codex 是否正在等待审批。
2. 打开终端，跑一条基础命令，例如 `git status`。
3. 新开一个对话，使用更小、更聚焦的 prompt。

如果你误取消了 worktree 创建并丢失了 prompt，在输入框中按上箭头键即可恢复。

### 终端问题

**终端看起来卡住了**

1. 关闭终端面板。
2. 用 <kbd>Ctrl</kbd>+<kbd>`</kbd> 重新打开。
3. 重新跑一条基础命令，例如 `pwd` 或 `git status`。

如果命令表现与预期不符，先在终端中检查当前目录与分支。

如果仍然卡住，等待所有活动对话结束后重启应用。

**字体渲染不正确**

Codex 在审查面板、集成终端以及应用内展示的其他代码中使用同一套字体。你可以在 Settings（`codex://settings`）面板中把该字体配置为 **Code font**。

### 环境允许联网，但动作仍被拦截

在对比单项设置之前，先看策略优先级。高优先级策略压过低优先级策略，即使低优先级策略看起来更具体。在同一条策略内，OS 特定的环境覆盖优先于全 OS 的环境覆盖，其次才是 Global。

某些网络要求有字段级的合并规则与运行时限制。受管代理监听端口与非回环代理监听端口不被云运行时支持；socket 规则的支持程度取决于执行路径。本机执行的合并行为与之相互独立。

对比生效策略，并测试预期允许与预期被拦截的动作。详细案例见站点文档路径 /docs/enterprise/managed-configuration。不要为了绕过一个失败的测试而放宽全局基线。
