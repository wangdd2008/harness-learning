# 02 总览与快速上手

> 本页覆盖：Pi 是什么（index）、快速开始（quickstart）、工作原理（how-pi-works）、日常使用（usage）。读完本页即可上手 Pi 并理解它的核心机制。

## index.md — Pi 概述

> 原文存档：[source/index.md](source/index.md)

**Pi 是什么**：Pi 是一个开源的、可编程的编码 Agent（coding agent），运行在终端里。它以极简设计为出发点——默认只有 `read`、`bash`、`edit`、`write` 四个工具，强调可控、可理解、可扩展。

**核心特性**：

- **本地运行**：CLI 直接在你的终端里跑，不上传代码。
- **默认模型**：`Claude Sonnet 4.5`（也可用 OpenAI、Gemini 等，见 03 页）。
- **工具极简**：默认四个工具 `read` / `bash` / `edit` / `write`，需要更多能力通过 MCP（08 页）与扩展（07 页）按需添加。
- **会话管理**：支持会话复用、分支（tree view），上下文自动压缩（05 页）。
- **可扩展性**：MCP 工具、扩展（extensions）、自定义提供方、虚拟模型路由、SDK / RPC 集成（07、08、09 页）。
- **用户界面**：交互式 TUI（select / confirm / input / 状态栏 / 全屏模式），可换主题（06 页）。

**学习路径建议**：

1. 先跑通 [quickstart.md](#quickstartmd--快速开始)，体验交互模式。
2. 读 [how-pi-works.md](#how-pi-worksmd--工作原理) 理解上下文与工具机制。
3. 按需深入：配置（04 页）→ 模型（03 页）→ 会话（05 页）→ 终端体验（06 页）。
4. 集成方向：MCP（08 页）→ 扩展（07 页）→ SDK / CLI 模式 / RPC（09 页）。

## quickstart.md — 快速开始

> 原文存档：[source/quickstart.md](source/quickstart.md)

**安装**（本地无 Node 环境时用 `curl` 安装）：

```bash
curl -fsSL https://pi.dev/install | bash
```

**启动**：

```bash
pi
```

首次运行会要求登录一个模型提供方：

- 默认走 **Claude**（Anthropic）；也可选 OpenAI、Google 等。
- 认证方式：`/login` 命令或浏览器 OAuth 授权。
- 也可用 `--provider` 显式指定，或配 `ANTHROPIC_API_KEY` 等环境变量（见 03、04 页）。

**第一个任务示例**：

```bash
# 在某个项目目录里启动并直接提问
pi "这个项目是做什么的？"
# 进入交互模式后持续对话、让它读代码、跑命令、改文件
```

**交互模式基本操作**：

- 直接输入消息 → Pi 规划并执行工具。
- `/quit` 退出；`/sessions` 查看历史会话；`Ctrl+C` 中断当前操作。
- 多行输入：`Shift+Tab` 切换多行编辑（见 06 页 keybindings）。

**下一步**：配模型（03 页）、自定义配置（04 页）、连接 MCP（08 页）。

## how-pi-works.md — 工作原理

> 原文存档：[source/how-pi-works.md](source/how-pi-works.md)

**一个请求的处理循环**：

1. **组装上下文**：从会话历史、分支摘要（compaction）、当前目录的 `.pi` 配置（skills、packages、prompt-templates、themes 等）组装上下文。
2. **发给模型**：按当前模式（build / plan / ask 等）构造系统提示词，请求模型给出回复。
3. **执行工具**：模型请求调用工具 → Pi 在沙箱/本地执行 → 结果回填上下文。
4. **迭代**：重复步骤 2-3 直到任务完成或模型给出最终答复。
5. **记录**：整段过程写入会话文件（session file，见 05 页 session-format）。

**上下文组装要点**：

- 会话历史按 token 预算管理，超出后触发 compaction（自动摘要旧消息，见 05 页）。
- 分支（fork/resume）可复用历史会话的不同时间点。
- 项目级资源（`.pi/skills`、`.pi/packages` 等）在每次请求时动态加载，改配置即生效（部分需要 `/reload`）。

**目录信任模型**：在未信任的目录里，Pi 不会加载 `.pi` 项目配置；`/trust` 或设置信任后才会加载（见 10 页 security）。

## usage.md — 在终端中使用 Pi

> 原文存档：[source/usage.md](source/usage.md)

**启动方式**：

```bash
pi                     # 交互模式，默认模型
pi "问题或任务"        # 直接给一条消息后进入会话
pi --continue          # 继续最近的会话
pi --fork <session>    # 从某个历史会话分支出新会话
pi --resume <id>       # 恢复指定会话
```

**三种常用模式（mode）**：

- `build`（默认）：可以读写文件、跑命令的完整编码模式。
- `plan`：只读分析、给方案，不落盘改动。
- `ask`：只问答，不执行工具（轻量）。

用 `/mode` 或 `--mode` 切换；`ask` 模式下不加载工具上下文，成本最低。

**工具使用习惯**：

- `read` 读文件；`bash` 跑命令（输出有截断保护）；`edit` / `write` 改文件。
- 每次工具执行结果都会显示出来，可在交互中追问、撤销。
- `/undo` 回退最近一次文件改动（部分场景）。

**会话与上下文**：

- `/sessions` 列出历史会话；`--resume` 恢复。
- `/compact` 手动压缩上下文；设置 `context.autocompact` 自动压缩（见 05 页）。
- 分支视图：全屏模式下 `Ctrl+T` 打开会话树（见 06 页），可看到各分支摘要，`--fork` 从任意分支续写。
