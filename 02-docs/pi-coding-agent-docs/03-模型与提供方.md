# 03 模型与提供方

> 本页覆盖：模型选择（models）、提供方与认证（providers）、模型配置参考（models-configuration）、自定义提供方（custom-provider）、虚拟模型路由（virtual-models）、本地模型 llama.cpp（llama-cpp / nvidia-rtx-llama-cpp）。本页是"Pi 怎么连模型"的完整地图。

## models.md — 选择模型

> 原文存档：[source/models.md](source/models.md)

**接入方式速查**：

| 你手头有什么 | 推荐做法 |
| --- | --- |
| 受支持的订阅 | `/login` 登录 |
| 提供方 API Key | `/login` 存入，或设环境变量 |
| 本地 GGUF 模型 | 连接 llama.cpp router |
| OpenAI / Anthropic / Google 兼容端点 | 写进 `models.json` |
| 自定义协议/认证的提供方 | 写扩展（custom-provider） |

**认证优先级**（多个凭据同时存在时）：运行时 `--api-key` > `auth.json` 存储凭据 > `models.json` 的 `apiKey` > 环境变量 / 环境云凭据。

**选择模型**：

- `/model` 打开模型选择器（只列出认证可用的模型）；`Ctrl+S` 保存为默认模型。
- `/thinking` 选择思考级别（thinking level：`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`），`Ctrl+S` 保存启动级别。
- `Ctrl+P` 在可用模型间循环；`/scoped-models` 控制循环范围。
- 会话会记录模型与思考级别的变更，`--resume` 恢复时不改动全局默认。

**配置兼容端点**（`models.json`，适配 Ollama / LM Studio / vLLM / SGLang / 各类代理）：

```json
{
  "$schema": "https://pi.dev/schemas/models.schema.json",
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [ { "id": "qwen2.5-coder:7b" } ]
    }
  }
}
```

- `apiKey` 支持 `$NAME` / `${NAME}` 环境变量插值、字面值、或 `!command` 命令输出；`$$`、`$!` 转义字面 `$` 与 `!`。命令在请求时执行、不缓存。
- 只给内置提供方设 `baseUrl` 可做代理转发，模型与认证保持不变。
- `modelOverrides` 只改元数据、不替换模型列表（未知 ID 被忽略）。
- `inputLimits.images.resize` 控制图片进入对话前的缩放/压缩（默认 2000×2000、4.5 MiB、JPEG 80）。
- `promptCache.short/long` 声明提供方缓存保留时长（秒），用于缓存预热。
- `samplingParams` + `samplingParamsByThinkingLevel`：OpenAI 兼容 API 按思考级别设置采样参数（temperature、top_p、top_k 等），仅对 `openai-completions` / `openai-responses` / `azure-openai-responses` 生效。

**分类器模型（classifier models）**：不做聊天，回答"选择/是/否/打分"类结构化问题。内置 TypeSafe Jev、Cloudflare Clef 系列、OpenAI GPT-6 Luna 等（见原文表格）。通过 `codemode` 脚本或扩展 `ctx.modelRegistry.classify()` 调用，不出现在 `/model` 中。

**图像模型（image models）**：如 OpenRouter 的 `google/gemini-2.5-flash-image`、`black-forest-labs/flux.2-pro`，通过 `codemode` 脚本或扩展调用，生成图不落盘。

**常见排障**：

- 模型不出现 → 检查提供方认证是否可用（`models.json` 里的模型需能解析凭据）。
- 只在某个 shell 能认证 → Key 来自环境变量而非 `auth.json`，启动 Pi 的进程必须带该变量。
- 远程机器登录弹浏览器 → 走 headless 认证流程，把重定向 URL / 授权码粘回 Pi。
- 兼容端点拒请求 → 检查 `api` 类型与 `compat` 设置。

## providers.md — 提供方与认证

> 原文存档：[source/providers.md](source/providers.md)

**两种认证方式**：OAuth 浏览器/设备流登录，或 API Key。

- `/login [provider]` 交互登录，凭据存入 `~/.pi/agent/auth.json`（**隐私文件，勿提交**）。
- `/logout` 删除存储凭据（不撤销提供方侧授权、不动环境变量）。
- 远程/无头机器：粘贴最终重定向 URL 或授权码完成 OAuth。

**主要提供方环境变量**（表内节选，完整见原文）：

| 提供方 | 环境变量 |
| --- | --- |
| Anthropic | `ANTHROPIC_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |
| DeepSeek | `DEEPSEEK_API_KEY` |
| Google Gemini | `GEMINI_API_KEY` |
| GitHub Copilot | `COPILOT_GITHUB_TOKEN` |
| OpenRouter | `OPENROUTER_API_KEY` |
| xAI | `XAI_API_KEY` |
| Qwen Token Plan | `QWEN_TOKEN_PLAN_API_KEY`（中国区 `_CN_` 版） |
| Moonshot AI | `MOONSHOT_API_KEY` |
| Kimi For Coding | `KIMI_API_KEY` |
| MiniMax | `MINIMAX_API_KEY`（中国区 `MINIMAX_CN_API_KEY`） |
| NVIDIA NIM | `NVIDIA_API_KEY` |
| Hugging Face | `HF_TOKEN` |
| TypeSafe | `TYPESAFE_API_KEY` |

- Anthropic 还支持 `ANTHROPIC_OAUTH_TOKEN` / `ANTHROPIC_AUTH_TOKEN`，以及工作负载身份联合（`ANTHROPIC_FEDERATION_RULE_ID` 等）。
- **密钥来自命令**：`auth.json` 中 `"key": "!security find-generic-password -ws 'anthropic'"` 形式，运行时执行并缓存到进程结束，不落盘明文。
- 凭据可带 `env` 对象覆盖该提供方的进程环境（如 Cloudflare 的 `CLOUDFLARE_ACCOUNT_ID`）。

**特殊提供方**：

- **Radius**（Earendil Works 自家 AI 网关）：`/login radius`，带组织级控制与分析，另有 MCP server。
- **OpenRouter**：带 Key 时按 `/models/user` 过滤可用聊天模型（受 guardrails 限制），后台刷新并离线缓存；区域端点改 `baseUrl`（如 `https://us.openrouter.ai/api/v1`）。
- **Azure OpenAI**：provider ID 为 `azure`；`AZURE_OPENAI_API_KEY` + `AZURE_OPENAI_BASE_URL` 或 `AZURE_OPENAI_RESOURCE_NAME`；部署名映射用 `AZURE_OPENAI_DEPLOYMENT_NAME_MAP`；Foundry 模型用 `api: "openai-completions"`。
- **Amazon Bedrock**：`AWS_PROFILE` / `AWS_ACCESS_KEY_ID` 等标准 AWS 变量，或 `AWS_BEARER_TOKEN_BEDROCK`，支持 ECS/IRSA。
- **Cloudflare AI Gateway / Workers AI**：`CLOUDFLARE_API_KEY` + `CLOUDFLARE_ACCOUNT_ID`（+ `CLOUDFLARE_GATEWAY_ID`）。
- **Google Vertex AI**：`GOOGLE_CLOUD_API_KEY` 或 ADC（`gcloud auth application-default login` + `GOOGLE_CLOUD_PROJECT` / `GOOGLE_CLOUD_LOCATION`）。

## models-configuration.md — models.json 字段参考

> 原文存档：[source/models-configuration.md](source/models-configuration.md)

文件位置：agent 目录（默认 `~/.pi/agent/models.json`）。加 `$schema` 获得编辑器校验。

**providers 级字段**：`name`、`baseUrl`（也作用于内置模型）、`apiKey`、`api`（如 `openai-completions` / `openai-responses` / `anthropic-messages` / `google-generative-ai`）、`oauth: "radius"`、`headers`、`compat`、`authHeader`、`models[]`、`modelOverrides`。内置 provider ID 只改该提供方；其他 ID 视为新增提供方（必须给 `baseUrl` + `api`）。

**models 条目关键字段**：

- `id`（必填，发给 API 的模型 ID）、`name`（显示名，参与 `--model` 匹配）。
- `api` / `baseUrl`：可覆盖提供方级。
- `reasoning`（是否支持思考）、`thinkingLevelMap`（各思考级别映射的提供方取值，null 表示不支持）。
- `input`（`["text"]` 或 `["text","image"]`）、`inputLimits`（maxRequestBytes / images.resize / maxPerMessage / maxPerRequest）。
- `cost`：`input` / `output` / `cacheRead` / `cacheWrite`（每百万 token 美元），可选 `tiers` 按输入 token 阈值分级计价。
- `promptCache`（short/long 秒）、`contextWindow`（默认 128000）、`maxTokens`（默认 16384）。
- `samplingParams` / `samplingParamsByThinkingLevel`、`headers`、`compat`。

**modelOverrides**：按模型 ID 覆盖内置/扩展模型的元数据（cost 等对象字段逐字段合并，其余整体替换）。

**compat（兼容性开关）**：描述"与标准 API 的已验证差异"，**不要仅凭端点自称兼容就开启**。按 `api` 分类：

- `openai-completions`：`supportsStore`、`supportsDeveloperRole`、`supportsReasoningEffort`、`supportsUsageInStreaming`、`supportsFinishReason`、`maxTokensField`、`requiresToolResultName`、`requiresThinkingAsText`、`thinkingFormat`（openai/openrouter/deepseek/together/baseten/zai/qwen/chat-template/string-thinking/ant-ling 等）、`chatTemplateKwargs`、`openRouterRouting`、`thinkingTokenBudgetField`、`supportsStrictMode`、`cacheControlFormat`、`sessionAffinityFormat`、`supportsLongCacheRetention`、`vllmPriority` 等。
- `openai-responses`（含 azure / codex）：`supportsMidConvoSystemMessages`、`supportsToolSearch`、`supportsExplicitPromptCacheMode`、`supportsMidConvoEffort`、`supportsMaxOutputTokens` 等。
- `anthropic-messages`：`supportsEagerToolInputStreaming`、`supportsLongCacheRetention`、`sendSessionAffinityHeaders`、`supportsCacheControlOnTools`、`supportsTemperature`、`forceAdaptiveThinking`、`supportsStrictTools`、`supportsMidConvoSystemMessages`、`allowedFallbackModels` 等。
- `bedrock-converse-stream` / `mistral-conversations` / `typesafe-system-one`（分类器图片输入格式 `imageInput`：assets/images/state-image-urls）等。

## custom-provider.md — 自定义提供方（扩展）

> 原文存档：[source/custom-provider.md](source/custom-provider.md)

**什么时候写扩展**：需要自定义认证、动态模型发现、自定义请求处理或流式传输时。若服务已实现受支持的 API，优先用 `models.json`。

| 需求 | 用 |
| --- | --- |
| 在受支持 API 后加模型 | `models.json` |
| 改端点/请求头 | `models.json` 或小扩展 |
| 动态发现模型 | 带 `refreshModels` 的提供方扩展 |
| 加 `/login` 流程 | 带 OAuth 配置的提供方扩展 |
| 实现不支持的线协议 | 带 `stream` / `streamSimple` 的提供方扩展 |

**注册**：扩展工厂里 `pi.registerProvider()`。两种形式：完整的 `Provider`（native 认证/过滤/发现/刷新/流式）或带 `ProviderConfig` 的 legacy 形式。新集成优先完整 `Provider`。

**常见场景**：

- 重定向现有提供方（保留内置模型目录，只改 baseUrl/headers）：

```typescript
pi.registerProvider("anthropic", {
  baseUrl: "https://gateway.example.com/anthropic",
  headers: { "X-Gateway-Key": "$GATEWAY_API_KEY" },
});
```

- 注册兼容端点 + 自己的模型目录（`api: "openai-completions"`，模型带 `type: "chat"` 与 cost 元数据）。
- 混合操作注册：`type: "image"` / `type: "classifier"` 模型 + `images` / `classifiers` 字段里的实现。
- `pi.unregisterProvider()` 移除动态提供方、恢复内置行为。

**认证**：静态提供方可从字面/环境变量/命令解析 key；OAuth 提供方出现在 `/login`，凭据存 `auth.json`；`openBrowserOnConfirm` / `copyCodeOnConfirm` 可禁用设备码流默认动作。**不要向普通日志写 access/refresh token、Authorization 头或完整响应**。

**自定义流式（streamSimple）**：只在无现成 API 实现可表达该服务时使用。规范要求：创建 assistant message → 请求建立后先发 `start` 事件 → 平衡发送 text/thinking/tool-call 事件 → 结算 usage/cost/stop reason → 恰好一个 `done` 或 `error` 终止事件 → 取消转 abort。必须调用 `options.onPayload` / `onResponse` / `onProviderStreamEvent` 等插桩钩子。

**测试清单**：普通/空文本、工具调用与结果、图片输入、usage 与成本核算、abort、上下文溢出、畸形/部分流、Unicode 边界、跨提供方会话交接、认证刷新与取消。

## virtual-models.md — 虚拟模型路由

> 原文存档：[source/virtual-models.md](source/virtual-models.md)

**概念**：虚拟模型是一个"可选中的模型"，每次请求由路由函数决定真正调度的物理模型。例如：简单问题走小模型、难题走大模型，用户只选一个模型。

```
selected (虚拟模型, 虚拟级别)  ->  dispatched (物理模型, 物理级别)
jev/auto:low                   ->  anthropic/claude-sonnet-4-5:high
```

选择记录在 `model_change` / `thinking_level_change` 条目；每次响应的 assistant message 记录真实物理模型（provider/api/model/thinkingLevel），跨模型回放与手动切模型一致。

**注册**：

```typescript
pi.registerVirtualModel({
  provider: "router",
  id: "auto",
  name: "Auto",
  thinkingLevels: ["low", "high"],
  route(request, ctx) {
    // 工具续做与重试保持在同一模型上
    const sticky = request.failed ?? request.previous;
    if (request.reason !== "user" && sticky) {
      return { model: sticky.model, thinkingLevel: sticky.thinkingLevel ?? "medium" };
    }
    const id = request.thinkingLevel === "high" ? "claude-sonnet-4-5" : "claude-haiku-4-5";
    return { model: ctx.modelRegistry.find("anthropic", id)!, thinkingLevel: "medium" };
  },
});
```

- `provider` 任意（物理提供方下列出需该提供方有凭据；无主提供方 ID 下始终可用）；`id` 不能与物理模型冲突；`thinkingLevels` 默认 `["off"]`。
- 注册/替换/卸载：重复注册同 ID 覆盖；`pi.unregisterVirtualModel(provider, id)` 卸载；SDK 用 `modelRuntime.registerVirtualModel(def)`。

**路由函数** `route(request, ctx) → { model, thinkingLevel, state? }`：

- `request.reason`：`user`（用户消息后的首请求）/ `continuation`（agent 循环中，如工具结果后）/ `retry`（失败自动重试，含压缩后）/ `direct`（循环外，如压缩摘要）。
- `request.previous` / `request.failed`：最近成功/失败响应的物理模型与级别；`continuation` 返回 `previous`、`retry` 返回 `failed` 可保持 prompt cache 与思考签名有效。
- `request.state`：路由状态，随会话分支存储、可穿越压缩，用于记录阶段（如 plan/build）或分类器结果；须 JSON 可序列化。
- 路由到无凭据模型或抛异常 → 请求以错误结束；虚拟模型不能再路由到虚拟模型。

**参考实现**：`examples/extensions/jev-router.ts`——先用 Jev 分类器选强模型做规划与首次编辑，再切到便宜模型收尾。

## llama-cpp.md — 本地模型（llama.cpp）

> 原文存档：[source/llama-cpp.md](source/llama-cpp.md)

**安装与启动 router**：

```bash
curl -LsSf https://llama.app/install.sh | sh
llama serve --no-models-autoload --host 127.0.0.1 --port 8080 -ngl all -c 32768
```

- **必须 router 模式**：不带 `--model` / `-m` / `-hf` 启动，否则是单模型模式。
- `--no-models-autoload`：加载显式交给 Pi 的 `/llama` 管理；`--jinja` 启用聊天模板与工具调用；`-ngl all` 全量 GPU 卸载；`-c 32768` 上下文大小。
- 单文件 GGUF 直接放模型目录；多模态/多分片模型放独立子目录。

**Pi 侧连接**：

- `/login llama.cpp` → 输入 router URL（默认 `http://127.0.0.1:8080`）与可选 API key。
- 环境变量：`LLAMA_BASE_URL` / `LLAMA_API_KEY`。
- `/llama` 管理模型：选择加载/卸载、从 Hugging Face 搜索下载（`HF_TOKEN` 用于门控仓库）、Esc 取消；**不会静默卸载、永不删除模型文件**。
- 加载/睡眠中的模型出现在 `/model`；`--no-models-autoload` 下先 `/llama` 加载再选。

**分类器**：llama.cpp 0.6.0+ 的决策模型（Julia-1 / Laya / Kev / lev / OpenJev 等）原生走 `/v1/systemone`；聊天模型也可当分类器（`llama-cpp-classify` API，从 next-token 概率读答案，temperature 可软化分布）。

**排障**：`curl http://127.0.0.1:8080/health` 与 `/models` 检查可达性；无模型检查 `--models-dir` 与目录布局；内存不足降 `-c` 或卸载其他模型；禁用该集成：settings `"extensions": ["-builtin:llama.cpp"]`。

## nvidia-rtx-llama-cpp.md — NVIDIA RTX + llama.cpp

> 原文存档：[source/nvidia-rtx-llama-cpp.md](source/nvidia-rtx-llama-cpp.md)

**思路**：NVIDIA Local AI Inference Recipes 给出针对特定显卡/模型调优的单模型 `llama-server` 命令；把该命令转成 router preset（`.ini`），Pi 就能多模型管理。

**转换规则**（recipe 命令 → preset 键）：

- `--ctx-size 65536` → `ctx-size = 65536`；无值选项 → `true`；去掉引号与反引号续行。
- 去掉 `--host` / `--port`（留在 router 命令行）；加 `load-on-startup = true`。
- `-hf` → `hf-repo`；`-hff` → `hf-file`；`-hfrd` → `hf-repo-draft`；`--spec-draft-model` → `spec-draft-model`。

**启动**：

```powershell
.\llama-server.exe --models-preset qwen3.8-27b.ini --host 127.0.0.1 --port 8080
```

- preset 段落名 = `/model` 里的模型 ID；检查就绪用 `curl.exe`（PowerShell 里 `curl` 是别名）。
- 注意 recipe 内存设定假设只有该模型用 GPU——`/llama` 里有其他已加载模型时先卸载。
