# 05 会话与上下文

> 本页覆盖：会话管理与分支（sessions）、会话文件格式（session-format）、消息类型（message-types）、上下文压缩参考（compaction）。Pi 的"记忆"机制全在这页。

## sessions.md — 会话管理

> 原文存档：[source/sessions.md](source/sessions.md)

**继续/切换会话**：

```bash
pi --continue   # 打开当前目录最近的会话
pi --resume     # 打开会话选择器
```

- 交互模式：`/resume` 打开选择器，`/new` 开新会话。
- 会话记录创建时的工作目录且**不会改变**；工具、`@path` 引用、项目配置、上下文文件都从该目录解析。
- 工作目录规则：`--continue` 用当前目录；`--resume`/`--session`/`/import` 用会话自己的工作目录；`--fork` 用当前目录开新会话。
- 会话工作目录已不存在时，交互模式会询问是否改在当前目录运行（每次都会问）；其他模式直接报错。
- `/name` / `--name` 命名会话；`/session` 查看当前会话文件、ID、消息数、token 与成本。
- 会话选择器支持搜索、重命名、删除（`Ctrl+D` 删除并确认，有 `trash` 时走回收站避免永久删除）。

**分支方式**（会话是树结构，回到早期节点不会抹掉离开的分支）：

| 动作 | 结果 | 适用场景 |
| --- | --- | --- |
| `/tree` | 在当前会话文件内移动 | 相关备选方案想留在同一会话 |
| `/fork` | 从早期用户消息创建新会话 | 备选方案要成为独立工作 |
| `/clone` | 把当前分支复制到新会话 | 想要当前状态的独立副本 |

- `/tree` 中选中用户消息可把文本放回编辑器，改后提交即产生新分支；选 assistant 回复则在之后以空编辑器继续。
- 离开分支时 Pi 可生成该分支摘要，附着到进入的分支上（保留下弃路径的有价值工作，不占全部消息）。

**上下文管理**：模型只收到活动分支（不是整个会话文件）。上下文接近模型上限时自动压缩（compaction）：加摘要、保留最近消息，**不删除原始会话条目**。`/compact [instructions]` 手动压缩（可附加"保留某主题"的指令）。压缩失败（提供方不可用）就修好提供方再 `/compact`；禁用自动压缩不影响手动命令。

**存储与分享**：

- 默认 `~/.pi/agent/sessions/`，按工作目录分组；`--session-dir` / `PI_CODING_AGENT_SESSION_DIR` / `sessionDir` 设置可改（CLI 最高优先）。
- `--no-session` 临时运行，退出后不可恢复。
- `/export` 导出 HTML 或 JSONL；`/share` 上传并返回查看链接（默认 Radius 制品，否则私有 GitHub gist；`sessionShareDestination` 可强制）。
- 导出/分享前先自查：可能含提示词、模型回复、工具参数、命令输出、文件内容、扩展消息。
- `/bug [description]` 向 Pi 开发者提交私有报告（含环境与提供方配置但不含凭据值），可选附带/省略/摘要会话转写；上传走 `radius.pi.dev` 或导出 zip。

## session-format.md — 会话文件格式

> 原文存档：[source/session-format.md](source/session-format.md)

**存储**：JSONL，每行一个 JSON 对象，`type` 字段区分条目类型；通过 `id`/`parentId` 构成树（原地分支，不新建文件）。

```
~/.pi/agent/sessions/--<path>--/<timestamp>_<session-id>.jsonl
```

**版本**：v1 线性（自动迁移）、v2 树结构、v3 将 `hookMessage` 角色改名 `custom`。加载时自动迁移到当前版本。

**条目类型**（每条都带 `type` / `id`（8 位 hex，可回退 UUID）/ `parentId` / `timestamp`，`session` 头除外）：

| 类型 | 用途 |
| --- | --- |
| `session` | 首行元信息（version/id/cwd，fork 出来的带 `parentSession`） |
| `message` | 对话消息（System/User/Assistant/ToolResult）。系统消息携带提示词与工具载荷：首个请求持久化完整 prompt sections + 工具声明，后续变更以 patch sections（null 移除）、`toolsAdded`/`toolsRemoved` 形式追加，按序重放即得当前状态 |
| `model_change` | 中途切换模型（可能是虚拟模型；assistant 消息记录实际应答的物理模型） |
| `thinking_level_change` | 思考级别变更 |
| `usage` | 非 assistant 消息的模型用量（如缓存预热 `cache_warm`），计入会话统计、不进 LLM 上下文 |
| `compaction` | 上下文压缩点：`summary` + `firstKeptEntryId` + `tokensBefore` + 完整系统提示词检查点 `systemMessage` |
| `context_edit` | 对早期上下文条目的一次性追加编辑（`targetId` + `replacement`，null=从模型上下文移除）；只影响未来模型上下文，原始条目与统计不变；分支相对（导航回编辑前恢复原贡献） |
| `branch_summary` | `/tree` 切分支时对弃用路径的摘要（`fromId` = 被摘要的旧叶） |
| `custom` | 扩展状态持久化，**不进 LLM 上下文**（虚拟模型路由状态用 `customType: "pi.virtual-model-state"`） |
| `custom_message` | 扩展注入的上下文消息，**进 LLM 上下文**（`content` + `display` 控制 TUI 显隐） |
| `label` | 用户书签/标记（`targetId` + `label`） |
| `session_info` | 会话元信息（如 `/name` 显示名） |

**上下文构建**：`buildContextEntries()` 从当前叶走到根，遇多个 compaction 取最新一个：compaction 条目在前 + `firstKeptEntryId` 起保留的非系统条目 + compaction 之后的条目。`buildSessionProjection()` 应用最新 context_edit（只换内容、保留角色与元数据）。`buildSessionContext()` 生成 LLM 消息列表：message → AgentMessage、compaction → 完整检查点 + compactionSummary、branch_summary → branchSummary、custom_message → CustomMessage。

## message-types.md — 消息类型

> 原文存档：[source/message-types.md](source/message-types.md)

**内容块（Content blocks）**：

- `TextContent`：`{ type: "text", text, textSignature? }`（签名是提供方专用、视为不透明）。
- `ImageContent`：`{ type: "image", data, mimeType }`（base64 数据）。
- `ThinkingContent`：`{ type: "thinking", thinking, thinkingSignature?, redacted? }`（redacted 块可无可见文本但有加密载荷）。
- `ToolCall`：`{ type: "toolCall", id, name, arguments, thoughtSignature?, namespace? }`（namespace 标识 OpenAI Responses 动态/命名空间工具）。

**Usage**：`input` / `output` / `cacheRead` / `cacheWrite` / `cacheWrite1h?` / `reasoning?` / `totalTokens` / `cost{...}`。`reasoning` 已含在 `output` 中，勿重复加；`cacheWrite1h` 是一小时保留的子集。

**基础消息**：

- `SystemMessage`：首条声明初始提示词与工具；后续可追加指令、按名替换/移除 prompt sections、增删工具。
- `UserMessage`：`content` 为 string 或 Text/Image 块数组。
- `AssistantMessage`：`api`/`provider`/`model`/`responseModel?`/`thinkingLevel?`/`usage`/`stopReason`（`pending`|`stop`|`length`|`toolUse`|`error`|`aborted`|`deferred`）/`errorMessage?`。`pending` 用于流式中的部分消息，`message_end` 的完成消息才是终态，`pending` 不落盘。
- `ToolResultMessage`：`toolCallId`/`toolName`/`content`/`details?`/`usage?`（嵌套模型工作）/`nestedCalls?`/`isError`。

**coding-agent 扩展消息**：

- `BashExecutionMessage`：直接 shell 命令（含 RPC `bash` 命令）产生，非 LLM 工具结果；默认在下个模型请求前转成 user 角色文本。
- `CustomMessage`：扩展注入的上下文消息（`customType`/`content`/`display`/`details?`，details 不进模型）。
- `BranchSummaryMessage` / `CompactionSummaryMessage`：由持久化的 branch_summary / compaction 条目生成。

**AgentMessage union** = System | User | Assistant | ToolResult | BashExecution | Custom | BranchSummary | CompactionSummary。底层 agent 包通过 TypeScript declaration merging 支持应用自定义角色——消费方要容忍未知角色。

## compaction.md — 压缩参考

> 原文存档：[source/compaction.md](source/compaction.md)

**两种摘要机制**：compaction（上下文超阈值或 `/compact`，摘要旧消息腾出上下文）与 branch summarization（`/tree` 导航时保留弃用分支上下文）。两者结构相似，摘要请求禁用 prompt-cache 写入（一次性提示词不值得缓存）。

**触发条件**：`contextTokens > contextWindow - reserveTokens`（默认 `reserveTokens = 16384`）。检查时机：每轮工具结束后、下一条 assistant 回复前；新用户消息前；提供方上下文溢出错误或早期 `stopReason: "length"` 时触发一次 compact-and-retry 恢复。

**工作过程**：找切点（向后累计 token 至 `keepRecentTokens`，默认 20000）→ 提取到切点的消息 → LLM 生成结构化摘要（有上次摘要时作为迭代上下文）→ 追加 CompactionEntry → 重建上下文（摘要 + firstKeptEntryId 起保留消息）。

**切点规则**：可在 user / assistant / BashExecution / custom 消息处切；**绝不在 tool result 处切**（必须跟它的 tool call 在一起）。单个用户消息段超过预算时产生 split user-message span：生成"历史摘要 + 段前缀摘要"两份合并。

**摘要格式**（Markdown）：Goal / Constraints & Preferences / Progress（Done/In Progress/Blocked）/ Key Decisions / Next Steps，compaction 另含 Critical Context；末尾附 `<read-files>` / `<modified-files>` 文件列表（跨压缩累计追踪）。

**序列化**：消息先经 `serializeConversation()` 转为 `[User]: ...` / `[Assistant]: ...` / `[Assistant tool calls]: read(path="...")` / `[Tool result]: ...` 文本（防止模型当对话继续）；思考块省略；工具结果截断到 2000 字符。

**扩展钩子**：

- `session_before_compact`：自动或手动压缩前触发，可 `{ cancel: true }` 取消，或返回自定义 `{ compaction: { summary, firstKeptEntryId, tokensBefore, usage?, details? } }`；`preparation` 提供 messagesToSummarize / turnPrefixMessages / previousSummary / fileOps / tokensBefore / firstKeptEntryId / settings；`reason` 为 `manual` / `threshold` / `overflow`。用 `serializeConversation(convertToLlm(messages))` 自选模型摘要（参考 `examples/extensions/custom-compaction.ts`）。
- `session_compact_failed`：压缩失败/中止时触发（telemetry 配对用），带 reason/errorMessage/aborted/willRetry/fromExtension。
- `session_before_tree`：`/tree` 导航前触发，可取消导航或提供自定义分支摘要。

**设置**：`compaction.enabled` / `reserveTokens` / `keepRecentTokens`；`compaction.modelOverrides` 按精确 `provider/modelId` 覆盖（如 1M 上下文模型设 reserveTokens 400000）。键大小写敏感；值必须非负安全整数；`enabled` 全局生效不按模型。
