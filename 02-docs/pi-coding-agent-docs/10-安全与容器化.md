# 10 安全与容器化

> 本页覆盖：安全模型（security）与隔离运行方式（containerization）。学习 Pi 前先看这条：模型生成的命令/代码不可信，Pi 用什么权限跑、就有什么权限。

## security.md — 安全运行

> 原文存档：[source/security.md](source/security.md)

**核心前提**：把模型生成的命令与代码当不可信输入。Pi 以启动它的账号权限读取/修改/执行文件，**不会在每次工具调用前征求同意**；扩展、包安装器、语言服务器等子进程同权限，除非操作系统/虚拟化边界限制。文件、注释、指令、命令输出、模型响应都可能通过 **prompt injection** 操纵模型——项目信任只控制启动时加载哪些项目资源，**不**使内容或后果变安全。

真正的安全来自限制 Pi 能访问/影响的文件、凭据、进程与网络服务。看转写、用项目信任、审查变更**都不是**安全边界。

### 运行方式对比

| 方式 | 受保护内容 |
| --- | --- |
| 直接以 OS 用户权限运行 | 该用户访问不到的东西；专用账号可收窄权限，但仍与其他用户共享 OS 与网络 |
| **整体**放进容器/VM/沙箱 | 未暴露给环境的主机文件与进程；暴露进去的凭据/网络服务仍可达——**通常最强实际选项** |
| Pi 在隔离环境外、仅内置工具在隔离内运行 | 主机资源对这些工具产生的动作受保护；Pi 本体与其他扩展仍在边界外——更窄的隔离 |

工作文件夹只控制资源发现与工具默认位置，**不能**阻止命令访问 Pi 进程可达的其他路径。无论哪种方式：只给任务所需文件与服务；凭据尽量留在环境外或用窄范围、短生命周期凭据；不需要网络就限制网络。

### 项目信任（Project Trust）

控制是否加载工作文件夹提供的大部分设置与资源，防止文件夹在你批准前静默加载可执行扩展。**注意**：

- 不是完整启动边界：Pi 在解析项目信任**之前**就读项目 `sessionDir` 设置来选/建会话；拒绝信任会跳过其余项目设置与受保护资源，但无法撤销那次初始会话目录查找。
- **不限制工具调用能访问/影响什么**：启动后启用工具仍用 Pi 进程的 OS 权限；文件夹里的指令内容也能影响模型。

**触发信任决策的资源**（从当前工作目录发现即触发）：`.pi/settings.json`、`.pi/mcp.json`、`.pi/extensions|skills|prompts|themes`、`.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`、当前目录或祖先目录的项目 `.agents/skills`。裸 `.pi` 目录不触发。

**授予后加载**：项目设置、`.pi/mcp.json` 的 MCP 服务器、`.pi` 下的扩展/技能/提示模板/主题/系统提示文件、项目设置配置的缺失包、项目本地/项目包扩展。**拒绝则跳过**以上（除初始 sessionDir 查找）。`AGENTS.override.md` / `AGENTS.md` / `CLAUDE.md` 等上下文文件**无论信任与否都加载**（除非禁用上下文加载）——文件夹里的指令永远当不可信输入。

**决策顺序**：CLI `--approve` / `--no-approve` 覆盖优先 → 无覆盖且有受保护资源时：① 用户级/CLI 扩展可处理 `project_trust` 事件（**第一个返回 yes/no 的拥有决定权**）→ ② 无扩展决定则查当前目录或祖先目录的已存决策（最近的适用）→ ③ 无则用全局 `defaultProjectTrust` 设置（默认 `"ask"`）。已存决策用规范路径存 `~/.pi/agent/trust.json`；`/trust` 为未来进程保存决策。

**非交互模式**：print/JSON/RPC 无法显示内置信任弹窗——无覆盖/扩展/已存决策时：`defaultProjectTrust: "always"` 加载受保护项目资源；`"ask"` 或 `"never"` 跳过。自动化单次运行用 `--approve`/`--no-approve`。

### 降低影响与便于恢复

- 只给任务所需文件与服务；重大改动前先快照/备份/版本控制；加载扩展与包前审查（扩展在 Pi 进程内执行）；优先窄范围短生命周期凭据；把结果应用到其他系统前审查 diff 与生成输出；导出/分享会话前审查（可能含提示词、工具参数、命令输出、文件内容与会话中暴露的凭据）。

### 报告安全问题

走仓库 Security Policy（github.com/earendil-works/pi 的 SECURITY.md），不要为安全敏感报告开公开 issue。本地 agent 的预期行为、不可信内容的 prompt injection、无内置沙箱、用户安装扩展/技能的行为，一般都在安全边界外——除非报告证明存在权限边界绕过或本用户原本没有的访问。

## containerization.md — 隔离环境运行

> 原文存档：[source/containerization.md](source/containerization.md)

隔离 Pi 完整进程，或让 Pi 留主机、把选中工具路由进隔离环境。

### 隔离方法对比

| 方法 | Pi 在哪 | 隔离什么 | 凭据处理 | 适合 |
| --- | --- | --- | --- | --- |
| Plain Docker | 容器 | Pi、内置工具、`!` 命令、扩展 | 凭据传入容器 | 直白的本地容器边界 |
| Docker Sandboxes | 托管沙箱 | Pi、内置工具、`!` 命令、扩展 | 提供方凭据留主机，由代理代换 | 托管本地隔离、不暴露真实 key |
| OpenShell | 本地或远程沙箱 | Pi、内置工具、`!` 命令、扩展 | 策略控制的凭据与推理路由 | 文件系统/进程/网络/凭据策略 |
| Gondolin 扩展 | 主机 | 内置工具与 `!` 命令 | 文件凭据留主机，但命令继承主机环境变量 | 本地微 VM 跑工具、保留主机界面 |

方法决定扩展跑在哪：整个 Pi 进程进隔离环境时扩展也进去；主机 Pi 经 Gondolin 委托内置工具时，其他扩展工具仍在主机（除非也委托）。

**决定 Pi 能访问什么**：读写主机挂载会让 Pi 改主机文件；挂载 `~/.pi/agent` 会暴露 Pi 凭据/设置/扩展/会话；传进容器的环境变量容器内可见；网络可能让代码/工具输出外泄；仅工具隔离约束不了主机 Pi 进程与不用隔离后端的扩展工具。只暴露任务所需的工作文件夹/凭据/网络目标；不想写回主机就用只读挂载或复制进出。

### Plain Docker

```dockerfile
FROM node:24-bookworm-slim
RUN apt-get update \
  && apt-get install -y --no-install-recommends bash ca-certificates git ripgrep \
  && rm -rf /var/lib/apt/lists/*
RUN npm install -g --ignore-scripts @earendil-works/pi-coding-agent
WORKDIR /workspace
ENTRYPOINT ["pi"]
```

```bash
docker build -t pi-sandbox -f Dockerfile.pi .
docker run --rm -it \
  -e ANTHROPIC_API_KEY \
  -v "$PWD:/workspace" \
  -v pi-agent-home:/root/.pi/agent \
  pi-sandbox
```

`pi-agent-home` 命名卷在多次运行间保留容器内设置/凭据/会话；**不要**挂载主机的 `~/.pi/agent`（除非容器确需访问）。验证：Pi 里跑 `!pwd` 应得 `/workspace`，其下改动写穿到主机挂载。

### Docker Sandboxes（托管沙箱）

完整 Pi 进程跑在托管沙箱，其代理可把真实提供方凭据留在主机、请求离开沙箱时代换。**配置凭据后再建沙箱；不要在沙箱内跑 `/login`**（会把真实凭据写进去）。Claude Pro/Max token：用 `claude setup-token` 生成，先 `sbx secret rm anthropic`（避免代理同时加 API-key 头），再 `sbx secret set-custom --host api.anthropic.com --env ANTHROPIC_OAUTH_TOKEN --placeholder 'sk-ant-oat01-{rand}'`（真实 token 从 stdin 读入，沙箱只拿 OAuth 形 placeholder，代理只对配置主机代换）。Anthropic API key 用 `sbx secret set anthropic`。

```bash
sbx run --kit "docker.io/sbx/pi-kit:latest" pi
sbx exec <sandbox-name> -- pi -p "list the failing tests"
```

### OpenShell（NVIDIA）

本地/远程沙箱，含文件系统/进程/网络/凭据/推理策略。每个沙箱需要活动 gateway：

```bash
openshell gateway add <gateway-url> --name <name>
openshell gateway select <name>
openshell sandbox create --name pi-sandbox --from pi -- pi
```

远程 gateway 不绑定挂载主机工作目录——需 `openshell sandbox upload/download` 显式传文件，或在沙箱内克隆仓库。推理路由可把原始模型凭据留在沙箱外；配置时把 Pi 指向 gateway 暴露的 OpenAI/Anthropic 兼容端点。

### Gondolin（本地微 VM）

保持 Pi 进程与文件凭据在主机，把内置工具与 `!` 命令路由进 Linux 微 VM。**注意**：VM 内命令继承主机进程环境——经环境变量传入的 key 在 VM 内可见，**不要**当凭据边界（除非移除敏感变量或改扩展环境处理）。需要 Node.js 23.6+ 与 QEMU。

```bash
mkdir -p ~/.pi/agent/extensions
cp -R packages/coding-agent/examples/extensions/gondolin ~/.pi/agent/extensions/gondolin
cd ~/.pi/agent/extensions/gondolin && npm install --ignore-scripts
cd /path/to/working-folder
pi -e ~/.pi/agent/extensions/gondolin
```

扩展把主机工作文件夹挂到 VM 的 `/workspace`（写穿回主机），覆盖 `read/write/edit/bash/grep/find/ls`。其他扩展工具仍在主机——加可能绕过 VM 边界的工具前先审查 Gondolin 示例。
