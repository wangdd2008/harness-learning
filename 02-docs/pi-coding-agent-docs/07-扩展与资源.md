# 07 扩展与资源

> 本页覆盖：扩展开发全 API（extensions）、技能（skills）、提示模板（prompt-templates）、Pi 包（packages）。这是 Pi"可编程能力"的核心，也是集成方案的重要一半。

## extensions.md — 扩展开发

> 原文存档：[source/extensions.md](source/extensions.md)

扩展是 TypeScript 模块，**运行在 Pi 进程内、拥有与 Pi 相同的系统权限**（可读提示词/工具调用/文件/凭据/会话历史）——只加载可信来源。

**放置位置**：

- `~/.pi/agent/extensions/*.ts`（全局）或 `.pi/extensions/...`（项目，需信任后加载）。
- 自动发现目录支持单文件、`*/index.ts`、带 `package.json` + `pi.extensions` 清单的子目录；发现只下探一层。
- `pi -e ./path.ts` 单次测试；`settings.json` 的 `extensions` 数组加更多路径。
- 自动发现位置的扩展可用 `/reload` 热重载。

**最小扩展**：

```typescript
import { type ExtensionAPI, isToolCallEventType } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("Extension loaded!", "info");
  });

  pi.on("tool_call", async (event, ctx) => {
    if (isToolCallEventType("bash", event) && event.input.command.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("Dangerous!", "Allow rm -rf?");
      if (!ok) return { block: true, reason: "Blocked by user" };
    }
  });

  pi.registerTool({
    name: "greet",
    label: "Greet",
    description: "Greet someone by name",
    parameters: Type.Object({ name: Type.String({ description: "Name to greet" }) }),
    async execute(toolCallId, params, signal, onUpdate, ctx) {
      return { content: [{ type: "text", text: `Hello, ${params.name}!` }], details: {} };
    },
  });

  pi.registerCommand("hello", {
    description: "Say hello",
    handler: async (args, ctx) => {
      ctx.ui.notify(`Hello ${args || "world"}!`, "info");
    },
  });
}
```

**可用导入**：`@earendil-works/pi-coding-agent`（类型/事件）、`@earendil-works/pi-agent-core`、`@earendil-works/pi-ai`（StringEnum 等）、`@earendil-works/pi-tui`（TUI 组件）、`typebox`（参数 schema）。Pi 把这些 import 映射到自己的副本（扩展共享类与注册表）；npm 依赖通过扩展目录旁的 `package.json` 安装。经 jiti 加载，TypeScript 免编译。工厂可 async（Pi 会等它完成再继续启动）。

### 事件系统（生命周期）

**一次 run 的生命周期**：

```
input → before_agent_start → agent_start → [turns] → agent_end → agent_before_settle → agent_settled
```

- `agent_end` 不是"最终空闲"信号（之后可能还有重试/压缩重试/排队跟进）；用 `agent_settled` 判断真正结束。
- 每一 turn：`turn_start` → 模型请求 → 工具执行 → `turn_end`（可追加条目、请求 continuation）。
- 模型请求钩子顺序：`context`（可改对话消息）→ `context_with_system`（可改完整转写）→ `before_provider_headers`（改请求头）→ `before_provider_request`（检查/替换 payload）→ `after_provider_response` → `provider_stream_event` + `message_start/update/end`。
- 工具调用钩子顺序：`tool_execution_start` → `tool_call`（**可拦截**，可改 input）→ `tool_execution_update` → `tool_result`（**可改结果**）→ `tool_execution_end`。

**会话生命周期**：`project_trust`（可返回 `{ trusted: "yes"|"no"|"undecided" }`，首个 yes/no 决定生效并抑制内置信任弹窗）→ `session_start`（reason: startup/reload/new/resume/fork）→ 操作 → `session_shutdown`。`/new` `/resume` `/fork` `/clone` `/reload` 都会 shutdown 旧实例→重新绑定→再 `session_start`。

**其他事件**：`session_before_compact`/`session_compact`/`session_compact_failed`、`session_before_tree`/`session_tree`、`session_info_changed`、`model_select`、`thinking_level_select`、`user_bash`（可拦截 `!`/`!!`）、`input`（可 transform/handled/continue）、`resources_discover`（贡献技能/提示/主题路径）、`ui_prompt_start/end`、`cache_warming_decision`（最后返回 action 者胜）、`mcp_servers_change`。

**处理器组合模式**：Notification（忽略返回值）/ In-place mutation（后置处理器看到改动）/ Chained transformation（拿到前置返回值，如 input/context/message_end/tool_result）/ Gate（拦截即停止默认路径）/ Last override。

### ExtensionContext（ctx）

- `ctx.ui`：`select/confirm/input/editor/notify` + `setStatus/setWidget/setFooter/setHeader/setTitle/setEditorText` + `setWorkingMessage/setWorkingIndicator` + `custom()` + `addAutocompleteProvider` + `setEditorComponent` 等（详见 06 页 tui）。
- `ctx.mode`：`"tui" | "rpc" | "json" | "print"`；`ctx.hasUI`：TUI/RPC 为 true，print/json 为 false。
- `ctx.sessionManager`：只读会话状态（getBranch/getEntries/buildContextEntries/getLeafId 等）。
- `ctx.modelRegistry`：模型/提供方访问；`streamSimple(model, context, options)` 做流式模型调用（能感知扩展注册的提供方，优于 `pi-ai/compat` 直接调用）。
- `ctx.signal`：agent 中止信号（turn 事件里有，空闲时 undefined）——用于 `fetch(..., { signal })` 等可中止工作。
- `ctx.isIdle()` / `ctx.abort()` / `ctx.shutdown()`（优雅退出，交互/RPC 模式延迟到空闲）。
- `ctx.compact({ customInstructions, onComplete, onError })`、`ctx.getContextUsage()`、`ctx.getSystemPrompt()`。

**命令上下文（ExtensionCommandContext）额外能力**（仅命令里可用，事件处理器里用会死锁）：`ctx.waitForIdle()`、`ctx.newSession({ parentSession, setup, withSession })`、`ctx.fork(entryId, { position, withSession })`、`ctx.navigateTree(targetId, { summarize, ... })`、`ctx.switchSession(path, { withSession })`、`ctx.reload()`。注意会话替换陷阱：`withSession` 只应在回调内使用新 ctx，旧捕获的 `pi`/`ctx` 会失效。

### ExtensionAPI 方法（节选）

| API | 作用 |
| --- | --- |
| `pi.on(event, handler)` | 订阅事件，返回退订函数 |
| `pi.registerTool(def)` | 注册 LLM 可调工具（加载期或运行期都行，同会话立即生效） |
| `pi.sendMessage(msg, { deliverAs, triggerTurn })` | 注入自定义消息（进 LLM 上下文）；deliverAs: `steer`（流式中，当前 turn 工具跑完后投递）/ `followUp`（agent 全部结束后）/ `nextTurn` |
| `pi.sendUserMessage(content, { deliverAs, expandPromptTemplates })` | 发送"用户消息"；流式中必须给 deliverAs |
| `pi.appendEntry(customType, data)` | 持久化扩展数据（**不进 LLM 上下文**） |
| `pi.setSessionName` / `pi.setLabel(entryId, label)` | 会话命名 / 条目打标签 |
| `pi.registerCommand(name, { description, handler, getArgumentCompletions })` | 注册 `/命令`（重名自动加 `:1` `:2` 后缀） |
| `pi.registerMessageRenderer / registerEntryRenderer / registerMarkdownTransformer / registerToolRenderer` | 自定义渲染 |
| `pi.registerShortcut` / `pi.registerFlag` | 快捷键 / CLI flag |
| `pi.exec(cmd, args, { signal, timeout, cwd, maxBuffer })` | 无 shell 执行命令（maxBuffer 默认 256MiB） |
| `pi.getActiveTools / getAllTools / setActiveTools(names)` | 管理工具启停（运行期可动态加载工具） |
| `pi.setModel / getThinkingLevel / setThinkingLevel` | 会话级模型/思考级别（不改全局默认） |
| `pi.events` | 扩展间共享事件总线 |
| `pi.registerProvider / unregisterProvider` | 动态注册/移除模型提供方（见 03 页） |
| `pi.registerVirtualModel / unregisterVirtualModel` | 虚拟模型路由（见 03 页） |
| `pi.registerMcpServer(name, config) / unregisterMcpServer` | 会话级注册 MCP 服务器（config 同 mcp.json 条目；注册不持久化，每次加载都要重注册；mcp.json 同名优先） |
| `pi.getSettings()` | 合并后的生效设置副本 |

### 自定义工具要点

- **schema**：`Type.Object(...)`（typebox），枚举用 `StringEnum`（所有提供方都认的纯 enum）。
- **promptSnippet**：一行摘要进 `<tools>` 段；**promptGuidelines**：附加到 `<rules>` 段的工具规则——**必须点名工具名**（"Use my_tool when..."），否则 LLM 不知道"this"指谁。
- **结果**：必须含 `content`（给 LLM）+ `details`（渲染与状态，类型跨结果一致）；嵌套 LLM 调用返回 `usage`；抛错或 `isError: true` 报错误；`terminate: true`（同批全部终止才生效）跳过后续自动 LLM 调用。
- **结构化输出**：声明 `outputSchema` 并返回 `structuredContent`（脚本/程序化调用方拿结构化数据，模型仍拿 text）。
- **并行执行**：默认并行；共享可变内存的工具设 `executionMode: "sequential"`。
- **文件变更队列**：改文件的工具必须用 `withFileMutationQueue(absolutePath, async () => {...})`——否则与内置 edit/write 并行时会出现"读到旧内容→覆盖写"的竞态。传 realpath 解析后的绝对路径。
- **覆盖内置工具**：同名注册即替换（无警告）；渲染按槽位继承（省略 renderCall 用内置）；`--no-builtin-tools` 只留扩展工具。实现必须匹配内置的结果形状（details 类型）。
- **远程执行**：内置工具支持可插拔 operations（`ReadOperations`/`BashOperations` 等），`createReadTool(cwd, { operations })` 可委托 SSH/容器；`user_bash` 可复用 `createLocalBashOperations()`；`createBashTool(cwd, { spawnHook })` 改命令/cwd/env。
- **输出截断**：内置上限 **50KB / 2000 行**；用 `truncateHead`/`truncateTail`/`truncateLine` 处理并告知 LLM 完整输出位置。
- **prepareArguments(args)**：schema 校验前改写旧参数（老会话恢复兼容），保持公共 schema 严格。

### 工具曝光（Tool Exposure）

| exposure | 行为 |
| --- | --- |
| `direct`（默认） | 激活时声明给模型，且可被其他工具调用 |
| `model-only` | 激活时声明给模型，永不可被调用（编排型/问用户型） |
| `codemode` | 注册即被 codemode 工具列出并可从脚本调用；不显式激活就不声明给模型 |
| `deferred` | 同 codemode，但 codemode 不列出；`tool_search` 可找到并激活 |
| `hidden` | 注册但不可达（撤回工具用） |

`namespace`（分组，MCP 风格）、`annotations`（readOnlyHint/destructiveHint/idempotentHint/openWorldHint，权限扩展可用它决定是否确认调用）、`reachesTools(input)`（声明调用可能触达哪些工具，`"all"` 或输入词）。

**调用其他工具**：`ctx.executeTool(name, args, { signal, onUpdate })`（只对 `ctx.tools` 列出的工具可用；失败返回 `isError: true` 而非 reject）；嵌套调用事件带 `parentToolCallId`，`toolCallId` 为 `<parent>/<n>`；结果以 `nestedCalls` 有界记录在调用方 result 上（不入转写）。

### 状态管理

- 有状态工具把状态存进**工具结果 details**，从 `getBranch()`（不是所有条目）重建——被放弃的分支是备选历史。
- 持久化但不想进模型的数据用 `pi.appendEntry()`（`custom` 条目）。

### 模式行为

| 模式 | ctx.mode | ctx.hasUI | 说明 |
| --- | --- | --- | --- |
| 交互 | `tui` | true | 完整 TUI |
| RPC（`--mode rpc`） | `rpc` | true | 对话框/通知走 JSON 协议；`custom()` 返回 undefined |
| JSON（`--mode json`） | `json` | false | 事件流到 stdout；UI 方法 no-op |
| Print（`-p`） | `print` | false | 扩展运行但无法弹窗 |

**错误处理**：扩展错误记日志、agent 继续；`tool_call` 错误拦工具（fail-safe）；`user_bash` 错误拦命令（不落入本地执行）。

**示例参考**（`examples/extensions/`，全文见原文表格）：hello/question/questionnaire/todo、dynamic-tools、structured-output、truncated-tool、tool-override、permission-gate、protected-paths、input-transform、custom-compaction、git-checkpoint、ssh、sandbox、subagent、custom-provider-*、jev-router、plan-mode、doom-overlay 等。

## skills.md — 技能

> 原文存档：[source/skills.md](source/skills.md)

技能给 Pi 特定工作的专用指令与配套文件。**使用时机**：比提示模板需要更多上下文、但不需要新的可执行集成点时。Pi 实现 [Agent Skills 规范](https://agentskills.io/specification)。

**结构**（目录含 `SKILL.md`，可带 `scripts/` `references/` `assets/`）：

```markdown
---
name: pdf-tools
description: Extract text and tables from PDF files. Use when reading, converting, or inspecting PDFs.
---

# PDF tools
Read `references/formats.md` before converting a document. Run scripts relative to this skill directory.
```

**加载机制**：启动时只把技能的 name/description/路径加进系统提示词（**不含全文**）；任务匹配时模型自己读 `SKILL.md`。模型可能不加载相关技能——`/skill:name` 强制加载；`/skill:name args` 把参数作为用户请求追加。`disable-model-invocation: true` 只允许显式命令调用。

**放置**：用户/项目 skills 目录（含 `SKILL.md` 的目录递归发现）；兼容 Agent Skills 位置 `~/.agents/skills/` 与 `.agents/skills/`（项目沿祖先目录发现到仓库根）。项目技能可让模型跑脚本/改文件——信任项目前先审阅。

**frontmatter 字段**：`name`（小写字母数字连字符，≤64）、`description`（≤1024，说明做什么+何时适用）、`license`、`compatibility`、`metadata`、`allowed-tools`（实验性）、`disable-model-invocation`。畸形 SKILL.md 与无描述技能不加载；重名保留首个并警告。

**验证/分享**：可发现位置运行 Pi 后查启动诊断与 `/skill:name`；编辑后 `/reload`；用 Pi 包经 npm/git 分发。

## prompt-templates.md — 提示模板

> 原文存档：[source/prompt-templates.md](source/prompt-templates.md)

提示模板把 Markdown 文件变成可复用的 `/` 命令。**使用时机**：复用同一提示词、不需要可执行行为时。

**创建**：`~/.pi/agent/prompts/review.md`：

```markdown
---
description: Review staged git changes
argument-hint: "[focus]"
---
Review the staged changes. Focus on ${1:-correctness, security, and error handling}.
```

文件名即命令名（`/review`）；`description` 进补全；`argument-hint` 用 `<必填>` / `[可选]`。

**参数替换**：`$1` `$2`（位置参数）、`$@`/`$ARGUMENTS`（全部）、`${1:-default}`（带默认）、`${@:N}`（从 N 开始）、`${@:N:L}`（N 起 L 个）；参数按 shell 风格引号解析（`/review "API compatibility"` 传一个含空格的参数）。

**加载**：用户/项目 prompts 目录（仅直接子 `.md`）；settings 与包可选嵌套文件/glob。项目模板在信任后成为命令。

## packages.md — Pi 包

> 原文存档：[source/packages.md](source/packages.md)

Pi 包把扩展/技能/提示模板/主题作为一个单元安装分发。

**安装**：

```bash
pi install npm:@example/pi-tools@1.0.0
pi install git:github.com/example/pi-tools@v1
pi install ./local-package
pi list          # 查看已配置包
pi remove <src>  # 移除
pi update --extensions   # 对账安装
```

- `-e npm:@example/pi-tools` 单次试用（缓存于 `~/.pi/agent/tmp/extensions/`，npm 精确版本钉死不复查）。
- 个人安装写入 `~/.pi/agent/settings.json`；`--local` 写 `.pi/settings.json`（需项目信任）。
- 启动时安装失败只警告并跳过，下次启动/`/reload` 重试。
- 来源：npm（钉版本）/ git（钉 tag/commit）/ URL（当 git）/ 本地路径（不复制）。

**创建**：普通目录，`extensions/` `skills/` `prompts/` `themes/` 约定目录自动发现；或 `package.json` 显式 `pi` 清单（相对包根路径，支持 glob 与排除）：

```json
{
  "name": "my-pi-package",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./src/extension.ts"],
    "skills": ["./resources/skills"],
    "prompts": ["./resources/prompts/*.md"],
    "themes": ["./resources/themes/*.json"]
  }
}
```

`pi-package` keyword 使其可被 [pi.dev/packages](https://pi.dev/packages) 画廊收录。

**依赖声明**：扩展 import 的运行时包放 `dependencies`；Pi 宿主提供的 5 个包（`pi-ai`/`pi-agent-core`/`pi-coding-agent`/`pi-tui`/`typebox`）必须放 `peerDependencies`（`"*"`）且**不要**打包进 `dependencies`（物理副本会绕过模块映射、产生重复类/注册表）。安装的包有独立模块根，不要依赖跨包共享依赖实例。

**资源选择**：settings 对象形式可收窄包内资源（省略=全部、`[]`=全不、`!pattern` 排除、`+path`/`-path` 精确）。`pi config` 可视化管理资源与内置扩展。

**changelog**：含扩展的包更新后，下次启动显示 CHANGELOG（`pi.changelogPath` 可改或 `""` 禁用；版本需匹配 `package.json` 的 `version` 字段）。

**范围与身份**：同一包可同时出现在个人与项目设置，项目条目默认替换个人条目（`autoload: false` 时作为过滤增量）；npm 按包名、git 按 URL（去 ref）、本地按绝对路径识别，避免重复加载。
