## keybindings.md — 快捷键参考

> 原文存档：[source/keybindings.md](source/keybindings.md)

**配置**：`<agent-dir>/keybindings.json`（默认 `~/.pi/agent/keybindings.json`）。每个动作标识映射一个键或键列表：

```json
{
  "$schema": "https://pi.dev/schemas/keybindings.schema.json",
  "app.session.new": "ctrl+shift+n",
  "app.session.tree": ["ctrl+shift+t", "alt+shift+t"],
  "tui.altScreen.pageUp": []
}
```

配置值替换默认；空列表禁用。改后 `/reload`。`/hotkeys` 查看当前生效快捷键。

**键语法**：`modifier+key`，修饰符 `ctrl`/`shift`/`alt`/`super`（可组合）。键：字母 a-z、数字 0-9、特殊键（escape/enter/tab/space/backspace/delete/home/end/pageUp/pageDown/方向键等）、f1-f12、符号。`super` 需要终端支持（通常经 Kitty 键盘协议）。

**常用动作速查**（完整表见原文）：

- 编辑器：`up/down`（历史浏览）、`ctrl+b`/`ctrl+f`（左/右移）、`alt+b`/`alt+f`（按词移动）、`ctrl+a`/`ctrl+e`（行首/行尾）、`backspace`/`delete`、`ctrl+w`（删词）、`ctrl+u`/`ctrl+k`（删到行首/行尾）、`ctrl+y`（yank）、`ctrl+-`（undo，Windows 用 `ctrl+z`）。
- 输入：`shift+enter` 或 `ctrl+j` 换行、`enter` 提交、`tab` 补全、`ctrl+c` 复制。
- 全屏：`pageUp`/`pageDown` 翻页、`ctrl+shift+f` 搜索转写（Windows/WSL 是 `ctrl+f`）、`ctrl+home`/`ctrl+end` 跳转首尾。
- 应用：`escape` 中断、`ctrl+c` 清空编辑器（再按退出）、`ctrl+d` 退出（编辑器为空时）、`ctrl+g` 外部编辑器、`ctrl+v` 粘贴（macOS；Windows/WSL `alt+v`）。
- 会话：`ctrl+p` 切路径显示、`ctrl+s` 切排序、`ctrl+n` 仅命名过滤、`ctrl+r` 重命名、`ctrl+d` 删除。
- 模型：`ctrl+l` 选模型、`ctrl+p` 下一个模型、`shift+ctrl+p` 上一个（Windows/WSL `alt+p`）、`shift+tab` 循环思考级别、`ctrl+t` 折叠/展开思考块。
- 消息：`ctrl+o` 折叠/展开工具输出、`ctrl+x` 复制消息、`alt+enter` 排队跟进消息（Windows/WSL `ctrl+q`）、`alt+up` 恢复排队消息到编辑器。
- 树导航：`ctrl+left`/`ctrl+right` 折叠/展开分支段、`shift+l` 编辑标签、`ctrl+u` 只看用户消息过滤、`ctrl+d` 默认视图。
- scoped-models：`ctrl+a` 全选、`ctrl+x` 清空、`ctrl+p` 按提供方切换、`alt+up`/`alt+down` 调整循环顺序。

Windows 注意：`app.suspend`（`ctrl+z`）无默认（Windows 终端不支持 Unix 作业控制）。

## tui.md — 终端 UI 组件开发

> 原文存档：[source/tui.md](source/tui.md)

`@earendil-works/pi-tui` 提供 Pi 的终端组件系统。**先选集成点**：

| 需求 | 用 |
| --- | --- |
| 选择/确认/输入/多行编辑 | `ctx.ui.select()` / `confirm()` / `input()` / `editor()` |
| 非阻塞反馈 | `ctx.ui.notify()` / `setStatus()` |
| 编辑器旁常驻内容 | `ctx.ui.setWidget()` |
| 替换头部/尾部/编辑器 | 对应的 `ctx.ui` 组件工厂 |
| 临时交互屏/浮层 | `ctx.ui.custom()` |
| 工具/会话条目自定义渲染 | 扩展 renderer |

**组件模型**：组件按给定宽度渲染一组终端行，可处理键盘/鼠标输入，状态或主题相关内容变化时须失效缓存并调 `tui.requestRender()`。行宽按**可见终端列**测量（ANSI 转义、宽字符、emoji 会改变显示宽度），用 `visibleWidth()` / `truncateToWidth()` / `sliceByColumn()` / `wrapTextWithAnsi()` 处理。

**内置组件**：`Text`/`Markdown`/`Image`/`TruncatedText`（内容）、`Container`/`VStack`/`HStack`/`Box`/`Spacer`（布局）、`Input`/`Editor`（文本）、`SelectList`/`SettingsList`（选择流）、`ScrollView`、`Loader`/`CancellableLoader`、`MouseRegion`。优先复用。

**键盘与焦点**：`matchesKey()` + `Key` 解析终端键盘输入；组件应使用注入的 `KeybindingsManager`。含文本光标组件要实现 `Focusable`，光标前放 `CURSOR_MARKER`、包 `renderFakeCursor()`（IME 定位依赖）；容器包裹 `Input`/`Editor` 时必须传递 `focused` 状态（否则 CJK IME 候选窗错位）。替换主编辑器用 `CustomEditor`。

**鼠标**：全屏模式路由归一化鼠标事件给组件，可标记已处理/捕获拖拽/请求焦点/请求渲染；未处理的滚轮滚到最近 `ScrollView`；**常规模式留给终端**（终端持有 scrollback）——每个交互都设计键盘路径。

**自定义屏/浮层**：`ctx.ui.custom()` 临时把交互区交给一个组件，组件通过回调 `done(...)` 结束并 resolve promise。完整示例见原文（pick-target 命令：render/handleInput/invalidate/requestRender/done 全生命周期）。等待用户输入时可传 `blocked: { kind: "question"|"permission"|"auth", message }` 让支持 Program Status 的终端显示阻塞态。`overlay: true` 画在现有内容上方；`OverlayHandle` 可改焦点、`setHidden()` 显隐。每个 custom 组件实例对应一次交互，重开交互要新实例。

**主题应用**：用传入回调的 theme；`theme.style("Done!", { fg: "success", bg: "toolSuccessBg", bold: true })` 组合样式；语义 token 作 `fg`/`bg`，另一位置用 `theme.colors.xxx` 具体色；`theme.appearance` 判断明暗。**不要**把带主题色的字符串长期存入应用状态（主题切换无法清除嵌入旧 ANSI）。

**性能**：渲染在交互路径上，按宽度/内容缓存昂贵布局并随 `invalidate()` 清除；保持默认视图紧凑。`PI_TUI_WRITE_LOG` 可抓原始 ANSI 流诊断。测试窄宽度/宽字符/重绘/主题切换/焦点切换/常规与全屏模式。

## themes.md — 主题

> 原文存档：[source/themes.md](source/themes.md)

**内置**：`system`（默认，跟随终端）/ `dark` / `light`。`system` 查询终端前景/背景色与 16 个 ANSI 色，保证正文 4.5:1 WCAG 对比度；终端明暗切换时重建。启动等终端回答最多 100ms，超时用 ANSI 回退。`system` 是保留名。

**选择**：`/settings` → Theme；保存为 `theme` 设置（`"dark"` 或自动模式的 `"light/dark"`，`/` 保留给该格式，主题名不能含 `/`）；`--use-theme light` 单次覆盖。

**自定义主题**：复制内置主题或新建符合 [schema](https://pi.dev/schemas/theme.schema.json) 的 JSON，存 `<agent-dir>/themes/<name>.json`。文件结构：

| 字段 | 必填 | 职责 |
| --- | --- | --- |
| `$schema` | 否 | 编辑器校验 |
| `name` | 是 | 唯一、不含 `/`、不能是 `system` |
| `appearance` | 否 | `"dark"`/`"light"`，省略时从颜色推断 |
| `vars` | 否 | 可复用颜色变量（可互相引用） |
| `colors` | 是 | 各 UI 角色颜色 |
| `export` | 否 | HTML 导出页面/面板背景覆盖 |

颜色六种写法：RGB hex（`#0af`）、OKLCH、OKHSL、256 色索引、变量引用、终端默认 `""`。对象严格：只接受文档化字段。Pi 热重载活动用户主题（仅 `<agent-dir>/themes/<name>.json`），其他来源改后 `/reload`。

**找颜色**：颜色按"界面角色"而非组件命名——通用（`accent`/`border*`/`text`/`muted`/`dim`/`success`/`error`/`warning`）、选择与全屏（`selectedBg`/`searchMatch*`/`scrollbar*`）、消息（`userMessage*`/`customMessage*`/`thinkingText`）、工具执行（`toolPendingBg`/`toolSuccessBg`/`toolErrorBg`/`toolTitle`/`toolOutput`）、Markdown（`md*`）、工具 diff（`toolDiff*`）、语法高亮（`syntax*`）、编辑器模式（`thinking*`/`bashMode`）、HTML 导出（`export.pageBg` 等）。5 个可选色有回退（如 `searchMatchBg`→`selectedBg`）。

**加载位置**：项目主题放 `.pi/themes/`（需项目信任）；也可通过 `themes` 设置或 Pi 包分发。重名报资源冲突。

## terminal-setup.md — 终端配置

> 原文存档：[source/terminal-setup.md](source/terminal-setup.md)

Pi 用扩展键协议区分 `Shift+Enter`/`Alt+Enter` 与普通 `Enter`。终端代理、复用器、IDE 内置终端可能丢弃这些信息。**排障表**：

| 症状 | 处理 |
| --- | --- |
| `Shift+Enter` 变成提交 | 看对应终端小节；tmux 见 tmux 页 |
| `Alt+Enter` 不排队跟进 | WezTerm / Alacritty / Windows Terminal |
| 全屏滚动异常慢 | iTerm2（Settings > Advanced > "Trackpad scrolls fast?" 设为 No） |
| 链接无悬停预览 | Ghostty（全屏按住 `Shift+Cmd`/`Shift+Ctrl` 用原生处理） |
| 内联图/颜色检测不到 | 覆盖检测能力 |
| IME 候选窗错位 | `export PI_HARDWARE_CURSOR=1` 或 `showHardwareCursor: true` |

- **Kitty / iTerm2**：无需额外配置。
- **Apple Terminal**：本地 macOS 修饰符回退（SSH 远程无效）。
- **Ghostty**：`Alt+Backspace` 失效加 `keybind = alt+backspace=text:\x1b\x7f`；**移除**旧 Claude Code 的 `shift+enter=text:\n` 映射（Pi 已绑 `Ctrl+J` 作换行）。
- **WezTerm**：`enable_kitty_keyboard = true`；macOS `Option+Enter` 默认全屏，需转发 `\x1b[13;3u`；WSL IME 用硬件光标。
- **Alacritty**：转发 `Alt+Enter` 为 `\u001b[13;3u`。
- **VS Code**：1.109.5+ 默认启用 Kitty 键盘协议；旧版给 terminal 加 `shift+enter` → `sendSequence \u001b[13;2u`。
- **Zed**：keymap.json 加 shift-enter / ctrl-- / ctrl-alt-] 绑定。
- **Windows Terminal**：原生 Windows 有本地 Shift 状态回退（WSL/SSH 无效）；`Shift+Enter` 加 actions `sendInput \u001b[13;2u`；`Alt+Enter` 被全屏占用，Pi 默认用 `Ctrl+Q` 跟进。
- **xfce4-terminal / Terminator / IntelliJ IDEA**：无法区分修饰 Enter，用 `Ctrl+J` 换行或换现代终端。

**覆盖检测能力**：`PI_HYPERLINKS` / `PI_IMAGE_PROTOCOL` / `PI_TRUE_COLOR`（或对应设置 `terminal.hyperlinks` / `terminal.images` / `terminal.trueColor`）。设置优先于环境变量；只在完整链路都支持时才强制，否则转义序列会破坏渲染。

**Program Status（OSC 7501）**：Pi 报告 `working`/`blocked`/`done`/`error`/`idle` 状态，供终端/agent 仪表盘显示；报告不含提示词与模型输出；tmux/screen 不转发；`PI_PROGRAM_STATUS=1/0` 强制开关。

## shell-aliases.md — Shell 命令配置

> 原文存档：[source/shell-aliases.md](source/shell-aliases.md)

Pi 为每条 Bash 命令启动独立的**非交互** shell——非交互 Bash 默认不展开别名、不加载交互式启动文件。

**命令来源与 shell**：模型调 `bash` 工具 / 你输 `!` `!!` → 解析出的 Bash；模型调 `powershell` 工具 → PowerShell 7（`pwsh.exe`）或 Windows PowerShell；扩展提供的 shell 工具 → 该扩展实现。

**解析顺序**（Unix）：`/bin/bash` → PATH 上的 `bash` → `sh`。Windows：`shellPath` → Git Bash → PATH `bash.exe`。

- `shellPath`：指定 Bash 可执行文件（Windows 路径反斜杠要双写）。
- `shellCommandPrefix`：每条命令前预置 setup（如 `"export CI=1"`），对 `bash` 工具与 `!`/`!!` 都生效；每次命令都跑，保持快速、无交互提示。
- **启用别名**：建 `~/.bash_aliases`（Bash 兼容语法），配 `"shellCommandPrefix": "shopt -s expand_aliases\nsource ~/.bash_aliases"`。**不要**把 `.zshrc` source 进 Bash。
- 排障：前缀对 `!` 生效但扩展工具不生效 → 该扩展自己管 shell；`shopt` 找不到 → Pi 回退到 `sh`；setup 命令等输入 → 移除交互命令。

## tmux.md — 在 tmux 中运行

> 原文存档：[source/tmux.md](source/tmux.md)

tmux 可能把 `Shift+Enter`/`Ctrl+Enter`/`Enter` 报成同一键。**启用扩展键**：

- **tmux ≥ 3.5**：`~/.tmux.conf` 加 `set -g extended-keys on` + `set -g extended-keys-format csi-u`。
- **tmux 3.2–3.4**：只加 `set -g extended-keys on`（Pi 支持 xterm `modifyOtherKeys`）。
- 配置作用于 tmux server——关掉会话重启 server（`tmux kill-server` 会终止该 server 全部会话，先保存工作）。
- 验证：`Shift+Enter` 换行、`Enter` 提交、`Alt+Enter` 排队（Windows/WSL 默认 `Ctrl+Q`）。若仍失效，先确认 tmux 外部的终端能报修饰键。

## windows.md — Windows 运行

> 原文存档：[source/windows.md](source/windows.md)

三种环境选择：

| 环境 | 命令环境 | 何时用 |
| --- | --- | --- |
| 原生 Windows + Git Bash | Git Bash 跑 `bash` 工具与 `!` | 文件与开发工具主要在 Windows |
| 原生 Windows + `powershell` 工具 | PowerShell 跑模型工具调用；`!` 仍用 Bash | 依赖 PowerShell 模块/Windows 原生命令 |
| WSL | WSL 发行版内 Linux Bash | 文件与工具链已在 Linux/WSL |

- **Git Bash**：装 Git for Windows 即可。解析顺序：`shellPath` → `%ProgramFiles%\Git\bin\bash.exe` → `%ProgramFiles(x86)%...` → PATH `bash.exe`。
- **powershell 工具**：`pwsh.exe`（PATH → `%ProgramFiles%\PowerShell\7`）→ `powershell.exe`（PATH → System32）；启动参数 `-NoProfile -NonInteractive -ExecutionPolicy Bypass`。把 `bash` 换成 `powershell`：`defaultTools: ["read", "powershell", "edit", "write"]` 或 `["-bash", "+powershell"]`。仅原生 Windows 进程可用。
- **WSL**：路径转换与 Git 分支轮询识别 `/mnt/<drive>`（自定义挂载根不支持）；legacy WSL `bash.exe` 启动器下 Pi 走 stdin 传命令避免引号问题。
- Windows Terminal 的修饰键配置见 terminal-setup 小节。

## termux.md — Android（Termux）

> 原文存档：[source/termux.md](source/termux.md)

Pi 可在 Android 上通过 Termux 运行（文本输入、文件工具、shell 命令支持；剪贴板文本经 Termux:API，**剪贴板图片不支持**）。

**安装**：Termux（GitHub/F-Droid，勿用 Google Play 旧版）→ `pkg update && pkg upgrade` → `pkg install nodejs git` → `npm install -g --ignore-scripts @earendil-works/pi-coding-agent` → `pi --version` 验证 → `cd 工作目录 && pi`。

**Android 共享存储**：`termux-setup-storage` 授权一次，之后 `/storage/emulated/0` 与 `~/storage/` 可用；只在需要时授权。

**剪贴板**：`pkg install termux-api`；Pi 用 `termux-clipboard-set` 复制、`termux-clipboard-get` 粘贴（仅文本）。

**环境提示**：在 `~/.pi/agent/AGENTS.md` 写 Termux 环境细节（共享存储路径、`termux-open-url`、`termux-open` 等），改后 `/reload`。

**排障**：剪贴板失败 → 确认 Termux:API app + termux-api 包都装了、先在 Pi 外验证；存储权限拒绝 → 重跑 `termux-setup-storage`；`pi` 找不到 → 检查 npm 全局 bin 目录在 PATH。
